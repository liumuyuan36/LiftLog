# V1.13：统一 DeepSeek 主模型

用户明确选择只保留一个模型负责产品中的AI任务。当前决策：记录整理、资料问答、训练时间方案选择和复盘重点选择均调用同一个服务端配置的DeepSeek主模型，默认deepseek-flash；每个任务仍使用独立Prompt和校验契约。RAG是资料检索流程，不是另一个模型。语音使用DeepSeek配套ASR工具，不声称文本主模型本身识别音频。

选择依据：既有资料问答对照中，DeepSeek 8题结构有效、7题通过严格AI语义复核；Atlas问答8题结构失败并出现内容错误。该对照只覆盖小样本知识问答、硬件和JSON约束不同，不能据此声称DeepSeek在所有训练记录题上优于Atlas。统一主模型主要用于减少双服务维护、用户选择负担与能力解释成本；本次另做记录和各任务接口验收。

Atlas、Qwen基座、LoRA权重、合成数据和历史评测保留为实验资产。生产服务器不再导入/启动Atlas worker，生产镜像不安装PyTorch、Transformers、Python或下载本地模型。UI移除服务选择，状态接口标明single-model；旧Atlas接口返回410，并要求用户刷新后重新确认DeepSeek处理方式，不把旧授权静默转成外部API调用。

所有AI调用需联网并消耗API余额，失败保留输入、无自动重试、无其他模型回退。手动记录、轨迹和已有记录的本地计算继续可离线。资料不足免调用仍由检索策略处理。模型结果须通过结构/证据校验，记录须由用户核对后保存。

产品案例将现行架构与历史Atlas实验区分展示。历史报告和冻结数据不改分数、不删除失败；旧PDF标为V1.11快照，不冒充当前线上架构。
